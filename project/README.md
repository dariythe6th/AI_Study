# MoodTune – AI Music Curator

MoodTune — это веб-сервис, который по текстовому описанию настроения, сцены или активности подбирает персонализированный плейлист. Сервис использует эмбеддинги текста (Sentence‑Transformers) и векторное хранилище (ChromaDB) для поиска треков, максимально соответствующих вашему описанию.

## 3. Требования и установка

### 3.1. Требования
- Python 3.10 или выше
- pip и virtualenv (рекомендуется)

### 3.2. Установка

```bash
# Клонируйте репозиторий
git clone <URL репозитория>
cd project

# Создайте виртуальное окружение
python -m venv .venv
source .venv/bin/activate   # Linux/Mac
# .venv\Scripts\activate    # Windows

# Установите зависимости
pip install --upgrade pip
pip install -r requirements.txt
```

## 4. Как запустить проект

### 4.1. Запуск сервиса (API + фронтенд)

```bash
cd project
source .venv/bin/activate
python -m src.api.main
```

Сервер запустится на `http://localhost:8000`. Откройте в браузере эту ссылку, чтобы увидеть интерфейс.

### 4.2. Использование API напрямую

Пример запроса:

```bash
curl -X POST http://localhost:8000/recommend \
  -H "Content-Type: application/json" \
  -d '{"text":"rainy day coffee shop", "limit": 5}'
```

Документация OpenAPI доступна по адресу `http://localhost:8000/docs`.

## 5. Данные

- **Источник:** High Popularity Spotify Data (предоставлен в репозитории).
- **Предобработка:** скрипт `src/data/loader.py` очищает CSV, добавляет недостающие колонки и создаёт «богатое» текстовое описание для каждого трека.
- **Индексация:** эмбеддинги вычисляются один раз при старте сервиса и сохраняются в `./chroma_db`. При последующих запусках индексация не требуется (если коллекция уже существует).

## 6. Тесты

В проекте реализованы **модульные** и **интеграционные** тесты для проверки ключевых компонентов. Все тесты используют библиотеку `pytest`.

### 6.1. Структура тестов

| Файл | Что тестирует |
|------|----------------|
| `test_models.py` | `MoodDetector` (определение настроения по тексту) и `TextEncoder` (генерация эмбеддингов) |
| `test_engine.py` | Основной движок рекомендаций: инициализация, получение рекомендаций, учёт настроения, формирование топ‑песен |
| `test_vector_store.py` | Векторное хранилище: добавление и поиск треков, обработка пустых результатов |
| `test_api.py` | API эндпоинты: `/health`, `/recommend`, регистрация/логин, обработка некорректных запросов |
| `integration_test.py` | Сквозные сценарии: полный цикл рекомендаций, связка детектора настроения с движком, реальный HTTP‑запрос |

### 6.2. Запуск тестов

Убедитесь, что виртуальное окружение активировано, и установлены зависимости (включая `pytest`).

```bash
cd project
source .venv/bin/activate
pytest tests/
```

Для запуска конкретного файла:

```bash
pytest tests/test_engine.py -v
```

### 6.3. Ожидаемые результаты

- Все тесты должны проходить успешно (или показывать `skipped`, если требуют авторизацию).
- Тесты, использующие реальный API (`test_api.py`), могут возвращать код 401 (если эндпоинт `/recommend` требует аутентификации) – это **не считается ошибкой**, а означает, что авторизация работает корректно.
- Тесты, которые инициализируют векторное хранилище, создают временную папку `./test_chroma` – она автоматически удаляется после завершения сессии (если не указано иное).

### 6.4. Фикстуры

В `tests/conftest.py` определена фикстура `sample_dataset`, которая предоставляет небольшой DataFrame для быстрого тестирования компонентов, не требующих полного датасета.
